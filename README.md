# 碰一碰评价表达助手

面向餐饮堂食场景的配置化 H5 交互原型，也是一个 AI 产品经理作品集项目。消费者通过商家专属二维码或 NFC 入口进入页面，记录真实体验，获得可编辑评价草稿，再自行复制到评价平台。

> 个人作品集原型，非商家、美团或大众点评官方产品，不代表任何合作或背书。产品不读取平台账号，不自动填写或提交评价，也不以奖励诱导正向评价。

- GitHub：[Yezz47/peng-assistant](https://github.com/Yezz47/peng-assistant)
- 公网演示：待Vercel部署完成后补充

## 产品问题

部分消费者并非缺少评价意愿，只是难以快速组织具体、自然的文字；商家则希望获得更可读的真实反馈。本项目把输入压缩为星级、结构化体验标签、菜品和一句话感受，再通过受约束的生成流程整理表达。

## 目标用户与边界

- 目标用户：完成堂食、愿意表达但组织语言有困难的消费者。
- 试点场景：餐饮堂食；不覆盖外卖、酒店和丽人。
- 产品边界：只生成可编辑草稿，由消费者确认、复制和自行提交。
- 作品集边界：低流量交互演示，不承诺生产 SLA，不接账号系统或大规模商家后台。

## 核心流程

1. 通过二维码/NFC进入 `/m/[merchantId]?entry=qr|nfc`。
2. 确认门店，避免评价错店。
3. 选择1—5星、负面/一般/正面体验，可选菜品并补充一句话。
4. 服务端校验商家、事实、隐私与星级倾向。
5. 生成可编辑草稿；AI不可用时自动降级到本地忠实表达模板。
6. 用户确认并复制，再自主选择评价平台。

## AI产品设计

- **商家上下文配置化：** 底层只维护一套程序，通过 `merchantId` 加载商家、品类、地址、招牌菜和平台入口。
- **结构化事实白名单：** 模型只能使用用户选择或输入的事实，不允许虚构菜品、服务和促销信息。
- **倾向一致性：** 星级与标签/文字出现明显矛盾时要求用户确认。
- **安全与隐私：** 对手机号、邮箱、证件号等风险内容进行提示和脱敏。
- **可控降级：** 未配置接口、超时或调用失败时回退本地模板，主流程仍可演示。
- **人在回路：** 草稿始终可编辑，复制前由用户承担最终确认。

## 当前演示状态

- 两份配置化商家档案，用于验证同一套程序加载不同商家上下文。
- 默认启用本地生成器，无需密钥即可完成全流程。
- 已预留 OpenAI-compatible 接口，但当前作品集部署不配置真实密钥。
- Supabase 代码为后续扩展预留；本阶段不配置数据库，因此不保存用户输入和生成稿。

## 技术结构

- Next.js 15、React 19、TypeScript、Zod
- 服务端生成与校验 API
- 本地商家种子 + 可选 Supabase 仓储适配
- Vitest 自动测试、ESLint、TypeScript 检查
- 目标部署：GitHub + Vercel

## 本地运行

```bash
pnpm install
pnpm dev
```

打开：

- 首页：`http://localhost:3000`
- 江南禧樽演示：`http://localhost:3000/m/jnxz_huhehaote_001?entry=qr`
- 重庆小面演示：`http://localhost:3000/m/cqxm_xingguang_001?entry=qr`

## 可选环境变量

复制 `.env.example` 为 `.env.local`。三项 AI 配置必须同时存在才启用真实模型：

```env
AI_API_KEY=
AI_BASE_URL=
AI_MODEL=
```

密钥只能保存在本地或 Vercel Environment Variables，不能提交到 GitHub，也不能使用 `NEXT_PUBLIC_` 前缀。

## 验证

```bash
pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

当前自动测试覆盖输入校验、本地生成、隐私脱敏、事实约束、诱导评价检测与星级倾向一致性。真实用户完成率、用时、复制率和内容符合度仍待小样本测试。
