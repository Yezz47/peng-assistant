# 🍚 小碰碗 · 小碗帮你说

> 一个帮助用户把真实餐饮体验更自然地表达出来的 AI 评价助手。

小碰碗聚焦餐饮评价场景。

用户不需要思考“评价应该怎么写”，只需要像平时聊天一样说出真实感受，例如：

> 牛肉挺嫩的，但是上菜有点慢，服务员态度还不错。

小碰碗会理解其中的菜品、服务、等待体验和整体态度，在 **不改变原意、不主动补充事实** 的前提下，将零散表达整理成一段更自然、完整、可以直接使用的评价。

---

## ✨ 项目效果

### 从「不知道怎么写」到「直接表达感受」

用户只需要描述真实体验：

```text
牛肉挺嫩的，但是上菜真的有点慢，
服务员态度还不错。
```

系统完成信息理解与表达整理：

```text
牛肉口感不错，比较嫩，这点挺满意。
不过上菜速度稍微有些慢，好在服务员态度很好，
整体体验还可以。
```

核心不是让 AI “写得更漂亮”，而是：

> **在保留用户真实态度的基础上，把话说清楚。**

---

## 🌱 为什么做这个项目？

餐饮评价看起来简单，但真实使用过程中存在一个明显问题：

很多用户其实有明确感受，却不愿意花时间组织语言。

最终大量评价会变成：

```text
还可以。
不错。
一般。
不好吃。
```

这些表达是真实的，但信息量很低。

另一方面，直接让通用大模型生成评价，又容易出现另一个问题：

> 为了让内容更加完整，模型可能主动补充用户没有提供的信息。

因此，小碰碗尝试解决一个更具体的问题：

**能不能让 AI 帮助用户表达，而不是替用户评价？**

## 🧩 核心功能

目前项目围绕一次完整的餐饮评价流程设计。

### 自然语言输入

不要求用户填写固定表单。

用户可以像聊天一样描述：

```text
环境不错，人也不算多，
但是那个意面感觉有点咸。
```

系统从自然语言中理解评价内容。

### 体验信息识别

从用户输入中提取与评价相关的信息，例如：

- 菜品与味道
- 服务体验
- 环境体验
- 等待时间
- 价格感受
- 用户整体态度

### 真实信息约束

生成内容只使用用户明确提供的信息。

例如：

```text
用户输入：
上菜有点慢。
```

系统可以表达为：

```text
上菜速度稍微有些慢。
```

但不会自行生成：

```text
足足等了四十分钟才上菜。
```

### 自然表达优化

对原始输入进行：

- 信息整理
- 语序调整
- 冗余删除
- 口语自然化
- 评价结构优化

同时尽量保持用户原本的语气与态度。

### 重新生成与修改

生成结果不是最终答案。

用户仍然可以：

- 重新生成
- 修改内容
- 调整表达方式
- 删除不需要的信息
- 复制最终评价

## 🔄 使用流程

```text
用户描述用餐体验
        ↓
理解当前表达内容
        ↓
识别评价要素与用户态度
        ↓
提取可使用的真实信息
        ↓
组织评价表达
        ↓
生成结果
        ↓
用户修改 / 重新生成
        ↓
复制使用
```

整个流程尽量保持轻量。

用户不需要学习 Prompt，也不需要理解模型背后的处理过程。

## 🧠 AI 回复逻辑

小碰碗没有直接采用：

```text
用户输入 → LLM → 最终评价
```

而是将生成过程拆分成几个步骤。

```text
User Input
    ↓
Intent Understanding
    ↓
Experience Extraction
    ↓
Fact & Attitude Constraint
    ↓
Response Generation
    ↓
Output Check
```

### 1. Intent Understanding

判断用户当前是在：

- 描述一次消费体验
- 补充评价信息
- 修改已有评价
- 调整表达语气
- 请求重新生成

### 2. Experience Extraction

从自然语言中整理核心体验信息。

例如：

```json
{
  "food": "牛肉比较嫩",
  "service": "服务员态度不错",
  "waiting": "上菜较慢",
  "overall_attitude": "中性偏正向"
}
```

### 3. Fact & Attitude Constraint

生成过程中遵循两个核心约束：

```text
不新增用户没有提供的事实
不改变用户原始评价态度
```

### 4. Response Generation

根据已确认的信息重新组织语言。

### 5. Output Check

检查生成结果是否存在：

- 新增事实
- 过度夸张
- 原意偏移
- 表达重复
- 不自然的模板化措辞

## 🎨 产品体验

小碰碗使用一个拟人化的小碗角色作为产品主要视觉形象。

角色设计采用：

- 简笔画
- 彩铅质感
- 小手、小脚
- 碗中保留少量米饭元素

整体视觉希望保持：

**轻松，但不过度娱乐化；友好，但不过度幼态。**

在评价过程中，小碗也会承担部分状态反馈功能。

例如根据用户当前表达：

```text
很失望
失望
一般
满意
很满意
```

呈现不同程度的角色反馈。

这样可以减少传统评分组件带来的机械感，让整个评价过程更接近一次自然交流。

## 📱 页面设计

当前核心页面主要围绕一次评价任务展开。

### 首页

负责快速说明产品作用，并降低首次使用门槛。

核心入口：

```text
“跟小碰碗说说这顿饭怎么样”
```

### 评价输入页

用户直接输入真实体验。

减少复杂选项和表单，优先保留自由表达。

### 结果页

展示整理后的评价结果，并提供：

```text
重新生成
继续修改
复制评价
```

等操作。

## 🎯 项目重点

这个项目并不追求实现一个复杂的大型 Agent。

目前更关注三个问题。

### 01. 用户输入成本

怎样让用户尽可能少操作，就能完成一条评价。

### 02. AI 输出可信度

怎样避免模型为了“写完整”而创造不存在的消费细节。

### 03. 回复自然度

怎样避免评价结果出现明显的：

```text
AI 味
模板感
客服式表达
```

让生成内容更接近日常真实评价。

## 💡 项目思考

小碰碗尝试验证的并不是：

> AI 能不能写出一条餐厅评价。

因为这个问题对于今天的大语言模型已经很容易。

真正希望验证的是：

> **在一个真实、具体的消费场景中，如何把通用的大模型能力转化成一个更低成本、更可信、更自然的产品体验。**
